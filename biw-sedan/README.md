# biw-sedan — ボディインホワイト (コンパクトセダン)

溶接デモ用のワークピース (CC0-1.0)。特定車種の複製ではない汎用 BIW。
**`collision_mode: authored`(weld-line-requests.md #3)の実証アセット**でもある。

![外観](docs/biw-iso.webp)

## 構成

- **ジョイントレスの単一リンク** `biw`。カタログ側は `category: workpiece` /
  `articulated: false` として「ロボットではなく障害物」を宣言する
- 全長 4.10 / 全幅 1.80 / 全高 1.20 m、質量 300 kg(重心 z = 0.689 m)
- 原点は車体中心・床パン基準 = 治具の位置決め点。
  X = 車両前後 (前が +X)、Y = 左右、Z = 上

BIW なのでクロージャ(ドア・ボンネット・トランクリッド)は付かない。
**エンジンルームとトランクが開いているのは正しい状態**。

## 形の作り方

平板の組み合わせではなく、**断面カーブを車長方向に変化させてロフト**している
(実車のボディサーフェスの引き方と同じ)。これで複合曲面になる:

- ロッカーのタックアンダー → 外へふくらむ下部サイド → 肩の**キャラクターライン** →
  ベルトラインから上の**タンブルホーム**
- ルーフは前後・左右の**二方向クラウン**
- 平面視でも前後端に向けて絞る

**ピラーとルーフレールは面ではなく掃引材**として作る。ラケットしたピラーを
矩形グリッドから切り出すと、どれだけ密度を上げても階段状になるため。
ホイールアーチにも**リップ材**を回している(実車にもあるし、円形開口が
グリッドに残すギザつきも覆える)。

## 実開口

| 開口 | 囲むもの |
|---|---|
| 前後ドア開口 (左右) | A/B/C ピラー・ロッカー・ルーフレール。**内側に折れたフランジ付き** |
| ウインドシールド | 左右 A ピラー / カウル / フロントヘッダ |
| バックライト | 左右 C ピラー / リアバルクヘッド / リアヘッダ |
| エンジンルーム | 左右フェンダー上端 / ラジエータサポート / ダッシュ |
| トランク | 左右クォーター上端 / リアパネル / パーセルシェルフ |
| ホイールアーチ ×4 | アーチリップ |

## スポット溶接用ピンチフランジ

ガンが**掴める形状**。板 2 枚合わせ (2.4mm) の実体で、collision も独立ピース。
突き出しはロッカーが 20mm、**ルーフディッチは 50mm**。

| フランジ | 位置 | ガンの入り方 |
|---|---|---|
| **ロッカーディッチ** ×2 | アンダーボディ外端から**下向き**、x 方向 2.1m | 車体下から、喉は前後方向 |
| **ルーフディッチ** ×2 | ルーフレール上端から**上向き 50mm**、x 方向 1.85m | 上方から、喉は前後方向 |

**向きは選べない。** 喉が 400mm あるので、喉は必ずフランジに沿って走る =
電極はタブの表裏を挟む。したがってタブは「面を向けている」だけでは駄目で、
**両面とも空間が空いている**必要がある。

**判定にはガンだけでなく「ロボットのフランジが車体の外にあること」も要る。**
ガン単体ならドア開口を通り抜ける姿勢が取れてしまうが、そこにガンを保持できる腕は
無い。ドア開口内のシルフランジを一度足して外したのはこれが理由(シルのタブは
同じ高さのボディサイドより 55mm 内側で、成立していた姿勢はすべてマウントが
車内にあるものだった)。

### なぜロッカーが下端なのか

要望では「ボディサイド下端の外側 (y≈0.90, z≈0.30)」だったが、**そこは成立しない**。
下部サイドは y=0.90 まで張り出す(キャラクターラインの下のクラウン)ので、
ロッカー角の 20mm タブは**車体自身の最大幅より内側**に埋まり、上側の腕がドア外板に当たる。
432 姿勢を総当たりして **0 成立**。アンダーボディ外端まで下ろすと車体下が全部空くので
全ステーション成立する。実車のジャッキアップフランジと同じ位置。

### ルーフレールを 40mm 幅にし、タブを 50mm 立てた理由

電極ホルダは**直径 40mm** で、タブから約 21mm 外側に立つ。レール上端が 90mm 幅だと
**フランジのどこを叩いてもホルダがレールに刺さる**(6/12 ステーション不成立)。
レールを 40mm 幅に絞るとホルダの立つ位置にレールが無くなり 12/12 になる。

さらに**突き出し 20mm ではホルダ半径 20mm を下回る**ため、有効な接触帯がタブ先端の
1/3 しか無かった。ルーフディッチだけ 50mm に上げて、接触帯全体を空中に出してある
(ロッカーは車体下が全部空くので 20mm のままで足りる)。

## 骨格

開口の中が素通しだと荷台にしか見えないので、実車にある骨格を入れてある:

- **フロントサイドメンバ** ×2 + **フロントクロスメンバ** — エンジンルームを梯子状に組む
- **ストラットタワー** ×2 — フロントアーチ上
- **リアサイドメンバ** ×2 と**トランクフロア**(スペアタイヤパン付き)
- **フロアパン** — トンネル付き、ドア開口から見える

## visual / collision

- **visual** = シェル全パネル 36 枚 (23,892 面)
- **collision** = 同じパネルを X 方向にスライスした**凸ピース 60 個**。
  サイドパネルは高さ方向にも 3 分割する(パネル 1 枚を丸ごと凸包にすると
  開口を飲み込んでしまうため)

**リンク単位でマージ + 穴埋めしてはいけない。** ドア開口・アーチ・窓が塞がる。
USD には `collisionApproximation: "convexHull"` として書き出されるので、
カタログはそこから `collision_mode: authored` を導出する。

## 著作 — Three.js + three-usd-robot

`authoring/` が著作経路。`biw.mjs` に形状定義があり、**Node のエクスポータと
ブラウザのビューアが同じファイルを import する**ので、ビューポートで詰めた形が
そのまま書き出される。ビルドステップ無し。

```sh
cd authoring && npm install
npm run view     # http://localhost:8731/viewer.html で対話的に確認
npm run export   # three-usd-robot で ../usd/biw-sedan.usda を書き出す
```

ビューア: `[s]` シェル / `[c]` collision ワイヤフレーム、視点 `[1]` 側面
`[2]` 前 3/4 `[3]` 上面 `[4]` 後 3/4。

**開口の縁が階段状になっていないかはここでしか分からない。** 静止画レンダリングでは
潰れて見えないまま通ってしまう(実際、初期版はそれで見逃していた)。
